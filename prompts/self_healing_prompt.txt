==================================================
COMMON FAILURE PATTERNS & HOW TO FIX THEM
==================================================

1. STRICT MODE VIOLATIONS:
   - Error: `strict mode violation: locator(...) resolved to 2 elements`
   - Fix: Use a more specific selector, scope to container (e.g. `page.locator("#navbarNav").get_by_role("link", name="Rooms")`), use `data-testid`, or append `.first` / `.nth(0)`.
   - If a Page Object method triggers a strict mode violation (e.g. inside `home_page.submit_contact_form`), you can perform the interaction directly in the test function using unambiguous locators (e.g. `page.locator("#name").fill(...)`, `page.locator("#email").fill(...)`, `page.locator("#description").fill(...)`, etc.).

2. MISSING PAGE OBJECT ATTRIBUTES:
   - Error: `AttributeError: 'HomePage' object has no attribute 'our_rooms_heading'` or `'AdminPage' object has no attribute 'login_heading'`
   - Fix: If the Page Object lacks an attribute or was generated with different names, locate the element directly using Playwright: `page.get_by_role("heading", name="Our Rooms")`, `page.get_by_role("heading", name="Login")`, or use attributes that exist on the Page Object.

3. ASSERTION FAILURES & TEXT MISMATCHES:
   - Error: `AssertionError: Locator expected to be visible ... waiting for get_by_text("Unauthorized")`
   - Look at the `Aria snapshot` or traceback in the pytest output! It shows the ACTUAL text and elements present on the page (for example: `- alert: Invalid credentials`).
   - Fix: Update the assertion to match what the page actually displays (e.g. `expect(page.get_by_text("Invalid credentials")).to_be_visible()`).

4. FORM VALIDATION & NOTIFICATION TEXT:
   - Inspect the pytest failure log for the exact error banner or message text produced by the application.
   - For Shady Meadows contact form: Phone validation error text is "Phone must be between 11 and 21 characters." or check alert class `.alert-danger`.

5. UNEXPECTED KEYWORD ARGUMENTS & JAVASCRIPT SYNTAX IN PYTHON:
   - Error: `TypeError: Locator.filter() got an unexpected keyword argument 'hasText'`
   - Fix: Python Playwright uses `has_text=...`, NEVER `hasText`. Replace any camelCase arguments with snake_case (`has_text=`, `has_not_text=`, `get_by_role`, etc.).
   - If a Page Object's locator has `hasText` or causes `TypeError`, bypass it and locate directly: `page.locator("div").filter(has_text=...).get_by_role(...)` or use simpler selectors like `page.locator("a[href*='/reservation/1']").first`.

6. URL MATCHING & TRAILING SLASHES:
   - Error: `AssertionError: Page URL expected to be 'https://.../admin/' Actual value: 'https://.../admin'`
   - Fix: Use regex matching to allow optional trailing slashes:
     import re
     expect(page).to_have_url(re.compile(r".*/admin/?$"))
     expect(page).to_have_url(re.compile(r".*/reservation/.*"))

7. PLAYWRIGHT SYNTAX:
   - Python Playwright uses SNAKE_CASE for assertions:
     - `expect(page).to_have_url(...)`
     - `expect(page).to_have_title(...)`
     - `expect(locator).to_be_visible()`
     - `expect(locator).to_contain_text(...)`

8. CREDENTIAL HANDLING:
   - When tests require authentication credentials:
     from utils.encryption import decrypt_value
     with open("input/credentials.json") as f:
         creds = json.load(f)
     username = creds.get("username")
     password = decrypt_value(creds["password"]) if "password" in creds else None
